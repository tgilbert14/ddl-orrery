# Council of the Guild · The Six Critics

Full verdicts and findings from the six cross-cutting seats, convened 2026-07-08 with the house rules in hand.
Every claim below was written against the live source. Part of the [v7 plan](../../PLAN.md).

---

## MITHRIL · Hub & First Impression seat — keeper of the first ten seconds

**Verdict.** On a desktop with a mouse, the hub genuinely earns the orrery frame: planets orbit on independent periods, z-sort behind and in front of a gold sphere that wears the face of whatever world you consider, and the warp floods out of the planet's live position — the hover-morph-click-aimed-warp chain is the best show-don't-tell in the whole piece. But it is a desktop thesis with a phone-shaped hole: under 700px the conceit collapses to a flat link list of CSS gradient dots with a 50%-alpha sphere ghosting behind it, untouchable because `#artifact-hit` is `display:none !important` — half the audience gets a brochure, not an orrery. The survey loop that justifies the frame (dots, seal, honor) is whispered in an 8px footer plate no first-timer will read, so the hub still parses as a pretty menu of eleven links with no stated reason to care. The Deep Deco reskin traded the hero headline for a 1.35rem tracked whisper whose subhead restates it, and the only usage instructions on the page are aria-hidden. Reduced-motion users get a hub that visibly ignores them: hovering retints the page accent but the sphere never repaints, and activating the Artifact does nothing perceivable. The label-collision defense (`nth-child` odd/even) is built on an adjacency assumption the physics itself destroys over minutes. The bones are excellent; v7's job is not more polish, it is making the frame legible to phones, first-timers, and assistive tech.

### Findings

- **Mobile hub abandons the flagship metaphor entirely** · `CRITICAL`
  Under 700px (src/02-hub.css `@media (max-width:700px) html.js .orbits { position: relative }`), the hub is a stacked list of `.planet-anchor` rows whose `.pa-dot` is a flat CSS radial-gradient — PlanetForge's procedural sprites never appear. `measureOrbit()` (src/05-core.js) parks the Artifact at `ART.cy = H*0.72` where `drawSky` paints it at `globalAlpha = 0.5` BEHIND the scrolling list's translucent `--glass` cards, and src/03b-deco.css kills its only interaction: `@media (max-width:700px) { #artifact-hit, .artifact-label { display:none !important } }`. No orbit, no hover-morph, no ripple, no reveal — the phone first impression is a dark brochure. This directly fails 'delightful on a mid-range phone' for the single most important screen.
  *Fix:* Give phones a seated compact orrery instead of deletion: (1) reserve a ~38svh stage block at the top of `.scene-hub` (a real DOM spacer so the list starts below it), point `measureOrbit()`'s phone branch at its center, draw the sphere at full alpha there, and re-enable `#artifact-hit` sized/clamped to that stage so tap → ripple/reveal works (it already can't steal list taps if it matches the sphere bounds inside the spacer). (2) At boot, bake each world once via `PlanetForge.drawMini` to an offscreen canvas → `toDataURL()` → set as the anchor's `.pa-dot` background-image; 11 tiny bakes, zero per-frame cost, and the list rows suddenly show the actual worlds. (3) On first tap of an anchor, fire the skin morph for ~400ms before `travel()` so mobile gets a taste of the hover chain.

- **Nameplate collision defense breaks by design: orbital periods scramble the adjacency it assumes** · `major`
  src/02-hub.css alternates label sides via `html.js .planet-anchor:nth-child(odd) .pa-label { bottom: calc(100% + 0.2rem) }` with the comment 'neighbors alternate label sides'. But `planetPos()` gives each world its own period (`95 + i*16` seconds, src/05-core.js), so the angular ORDER shuffles continuously — within a few minutes two odd-index worlds (both labels-above) pass each other and stack their nowrap nameplates ('The Drillyard', 'Stormwall' ≈ 95–110px wide) at identical y. It's worst at the flattened ellipse's left/right ends where 11 anchors compress horizontally (rx up to `min(W*0.44, r*2.9)`, ry ~0.27·rx). On a long-idle hub or during the Grand Tour's orbit breathers, colliding labels are guaranteed, and the hub reads as noise exactly when someone is staring at it.
  *Fix:* Assign label side per frame from live geometry instead of DOM parity: in `drawWorld` you already write `--pax/--pay/--psize/--pdim` per anchor — add a class toggle `a.classList.toggle('pl-above', p.depth < 0)` (far-side above, near-side below; far labels are already dimmed by `--pdim` so stacking there is cheap), plus a 1D declutter for same-side pairs: each frame (or throttled to ~4Hz) sort the same-side anchors by x, and when two are within ~90px flip the later one. One class toggle per anchor per pass — no layout thrash beyond what the per-frame custom-property writes already cost.

- **Reduced-motion hub is interactively dead: skin morph never paints, Artifact activation does nothing perceivable** · `major`
  In `tint()` (src/05-core.js) the hover path calls `SphereForge.setSkin(slug)` then guards `if (!skyTask && !reduced()) Orrery.startAmbient()` — under rm nothing ever calls `drawStatic()`, so the canvas holds its boot frame. SphereForge.draw's rm path (`if (reduced2) { curSkin = wantSkin }`, src/05c-sphereforge.js) is exactly the 'instant designed swap' promised, but it only executes on the next draw, which under rm happens only on resize. Result: the page accent retints (`--acc` is a CSS write) while the sphere visibly ignores the hover. Worse, `touchArtifact()` guards the entire visual response with `!reduced()`, and `ripple()`/`ping()` early-return on `rm()` — so a keyboard/rm user activating a button labeled 'The sphere. Unsurveyed. Activate to sound it.' gets zero feedback unless audio is on. That violates the house rule that reduced motion means designed end-states, not stripped interactions.
  *Fix:* One-line core fix: in `tint()`/`untint()` add `else if (reduced()) drawStatic();` — the rm branch of `draw()` then performs the instant skin swap on that single repaint. For the Artifact: under rm, make `touchArtifact()` still (a) call `drawStatic()` so the swap/reveal skin path can paint a held pose, and (b) acknowledge in DOM — flip `#artifact-label` to 'Object 0 · it heard you' for ~2s (text swap, rm-safe) and/or draw one static sonar ring for a beat (drawSonar's rm branch already knows how to render a designed still ring).

- **The survey game — the hub's whole reason to care — is invisible at first contact** · `major`
  The loop that makes the orrery more than a menu (markSurveyed → `.pa-tick` → survey dots → completion seal → 'Master surveyor' honor, src/05-core.js) announces itself only via an 8px-dot brass plate pinned bottom-left (`.survey-log`, src/03b-deco.css) at `--fs-label` scale, plus a checkmark hidden inside a hover-revealed nameplate. Nothing on the hub says 'survey all eleven'; `#hud-loc-name` says only 'Orbit · choose a world'; `#artifact-label` says 'Object 0 · unsurveyed' forever — it never changes after 3 touches trigger the biomech reveal, nor after 11/11 completion. A first-time visitor has no stated goal, no visible progress, and no hint that the Artifact reacts to persistence, so the hub reads as a pretty nav.
  *Fix:* Surface the loop in the chrome that's already there: (1) in `setScene('hub')`, after any world has been surveyed, set `locName.textContent = 'Orbit · ' + surveyed.size + ' of 11 surveyed'` — one string, updates every homecoming. (2) Swap `.hub-hint` after the FIRST return to orbit: 'One world surveyed. Ten remain.' using the existing `hint.dataset.home` restore machinery from TourController. (3) Let the Artifact's plate narrate its arc: after `artTouches >= 3` set 'Object 0 · something moved beneath'; on completion rite set 'Object 0 · it knows you now'. All DOM text writes, zero canvas cost, and the frame suddenly has stakes.

- **The only instructions on the page are aria-hidden, and they're wrong for half the devices** · `major`
  src/04-body.html: `<p class="hub-hint microlabel" aria-hidden="true">Choose a world · Tab to cycle · Enter to travel · it holds the center</p>`. This is the sole usage guidance and it is (a) hidden from exactly the assistive-tech users who most need 'Tab to cycle / Enter to travel', and (b) shown verbatim on phones where Tab/Enter is meaningless and hovering ('it holds the center' presumes the desktop artifact) doesn't exist. The tour's closing note and the surveyor honor also get swapped into this same aria-hidden node, so those payoffs are silent for AT too (the tour has its own live plate, but the honor line does not).
  *Fix:* Split the hint's duties: keep the poetic line visible, but remove `aria-hidden` and make the text input-aware at boot — `matchMedia('(pointer: coarse)')` picks 'Tap a world to travel · the artifact holds the center' vs the current keyboard line (one `textContent` write in bootOrrery; the `dataset.home` stash already centralizes the resting line). Add an sr-only paragraph inside `nav.orbits` ('11 links. Enter travels to a world; Escape returns to orbit.') so screen-reader users get real operating instructions where their focus actually goes.

- **Whisper-hero: the plaque caps the headline at 1.35rem and the subhead repeats it** · `minor`
  src/03b-deco.css `.hub-h1 { font-size: clamp(1.1rem, 0.95rem + 0.8vw, 1.35rem); font-weight: 300 }` overrides the 4.2rem `--fs-hero` (now a dead token in src/01-tokens.css). The h1 'Eleven worlds. One clock. One artifact, holding the center.' and `.hub-sub` 'Eleven hand-built worlds hold their orbits around something older…' say the same sentence twice in a lockup that maxes out around 44rem wide. On desktop the sphere carries the first impression so the engraved whisper is a defensible choice — but on mobile (where the sphere is a background smudge, see finding 1) the entire above-the-fold is small tracked text with no visual anchor, and the redundancy wastes the only two lines you get.
  *Fix:* Make the sub do a different job than the h1: state the mystery/action instead of restating the inventory — e.g. 'Hover a world and the artifact answers. Survey all eleven.' (which also fixes goal-invisibility for sighted users). Delete or re-point `--fs-hero` so the token file stops lying. Consider one plaque scale notch at ≥1200px (clamp max ~1.6rem) so big desktops don't read the flagship's title at caption size.

- **Phone footer congestion: fixed transparent HUD wraps to 3–4 rows and sits over list content** · `minor`
  `.hud-bottom` (src/01-tokens.css) is fixed, background-less, and centered; at 375px the long credits span ('Hand-built by … you are standing in the source') wraps 2–3 lines, plus the tour button, plus the survey count row forced to `order:-1; flex-basis:100%` (src/03b-deco.css `@media (max-width:1100px)`). That stack exceeds the `.scene` bottom padding of 4.5rem (src/02-hub.css), so on phones the last planet anchors scroll up underneath unbackgrounded 0.72rem footer text — two layers of small type over each other, both semi-legible.
  *Fix:* At ≤700px: shorten the credits (wrap the middle clauses in a span hidden by CSS, keeping 'Hand-built by Desert Data Labs · source'), give `.hud-bottom` the existing `--glass`/plaque treatment so it reads as a bar instead of floating words, and raise `.scene { padding-bottom }` to ~7rem in the same query so the list clears it. Three CSS edits, no JS.

- **Invisible-but-clickable nav during the approach cinematic** · `minor`
  During `runApproach()` the anchors animate `approach-anchor` from `opacity: 0.001` with delays up to `3.45s + i*0.07s` (src/03b-deco.css keyframes block), but opacity-only animation leaves them fully interactive: for the first ~3.5s of a user's very first visit, 11 invisible 44px+ targets and a ~500px invisible `#artifact-hit` are live in the middle of the viewport. A stray early click both skips the cinematic (capture-phase `skip`) AND lands on whatever unseen anchor is under the cursor — the user can be warped to a world before they have ever seen the hub.
  *Fix:* One rule: `html.approaching .planet-anchor, html.approaching #artifact-hit { pointer-events: none; }`. The capture-phase pointerdown still aborts the cinematic instantly (it's on `window`, not the anchors), the settle removes `.approaching` so the same gesture's second click travels normally, and nobody warps blind. Keep keyboard as-is — `keydown` skip already resolves before Enter can activate a focused anchor.

- **Artifact plate label collides with bottom-passing nameplates and never earns its keep** · `polish`
  `placeArtifactDom()` (src/05-core.js) pins `#artifact-label` at `ART.cy + ART.r + 30`; a near-side world at the ellipse bottom (`y ≈ ART.cy + ART.ry + bob`, full `--pdim`) puts its below-side nameplate within ~15–20px of the same line — at 0.58rem brass vs 0.92rem white, the overlap reads as a smudge. The engine already computes exactly the geometry needed to know this is happening.
  *Fix:* In `drawWorld`, when a near-side world's x is within ~120px of `ART.cx` and depth > 0.7, write a `--alab-dim: 0.15` custom property on the label (mirror of the existing `--pdim` occlusion trick) so the plate yields to the passing world; restore to 0.82 otherwise. Alternatively move the plate inside the sphere's lower rim (`ART.cy + ART.r*0.78`), where nothing else ever draws.

- **The Grand Tour — the best demo-reel feature — is undiscoverable** · `polish`
  TourController (src/05-core.js) is a genuinely impressive kiosk autopilot, but its only entry point is a footer button labeled 'Tour' at `--fs-label` (0.72rem) next to the credits (src/03b-deco.css `#tour-toggle`). No first-time visitor scans the footer of a full-screen space scene; the feature that best shows off the whole system will be found by approximately nobody, including the hiring managers this portfolio exists for.
  *Fix:* Give it one hub-level mention: append '· or take the tour' to the input-aware `.hub-hint` (finding 5) as a real inline link/button that proxies `TourController.start()`, and after ~20s of hub idle (no pointer/keys — the comet scheduler already tracks idle-ish state) pulse the footer button once via the existing `tour-scan` keyframe. Zero new machinery, and the autopilot finally gets an audience.

## MITHRIL — Game Feel & Interaction Design seat

**Verdict.** This is the best-engineered screensaver I have ever reviewed: craft 9/10, play 3/10. The complete verb list for a visitor is: hover a planet, click a planet, click the sphere, press Esc, press five buttons, and type one cheat code — everything else is watching, and the copy admits it ("Stay a while", "Keep watching", "Wait for the slow turn" are literal w-note captions). Five of the eleven worlds — including the four most beloved tropes: Dune worm, outrun riders, Matrix rain, and an ARCADE CABINET — have zero interactivity; Arcadia's ship aims and fires itself off Math.random() while the visitor, hands full of the most game-literate iconography on the page, gets to do nothing. The hover loop at the hub is genuinely excellent (accent retint, Artifact skin morph, 1.18x canvas swell, two-note scale preview — that is real juice), the warp is a solid 7/10 that lacks only anticipation frames, but button feel is 4/10: no :active state anywhere in the codebase, four of the five toys dispatch events the score never answers, and the beacons toy silently swallows presses for ~10 seconds mid-run. The survey-log progression loop — the one system that could convert wandering into a game — stores its collection in sessionStorage, so the meta-game wipes on every new tab and pays out a 12px dot when finished. The frame itself needs to shift from "museum with five buttons in the back half" to "every scene has one satisfying toy, and the toy answers in paint AND sound within one frame."

### Findings

- **Five marquee worlds are zero-verb screensavers** · `CRITICAL`
  dust-sea, velocity, grid, abyssal, and arcadia (06-worlds.js) accept no input at all — no pointer, no click, no key. These are the FIRST five worlds in WORLDS order and carry the strongest tropes. Worst case is fx.arcadia: the player ship random-walks (st.shipTargetX = shipMin + Math.random() * (shipMax - shipMin)) and fires on an 8-13s RNG timer (st.nextShot). It is an arcade the visitor cannot play. Meanwhile all five w-toy buttons live in worlds 6-11, so a visitor exploring in order sees six scenes before discovering the site has buttons.
  *Fix:* Give each a one-verb toy wired to state that already exists, ~15-25 lines each: ARCADIA — pointermove sets st.shipTargetX to cursor x, click/tap fires the pooled shot at the nearest live invader (reuse st.shot + reservoir pick, add a 600ms cooldown). GRID — click ignites a white trace in the tapped column (c.traceUntil = clock + 520 and the vertical fillText burst already exist in the nextTrace branch; just index C by floor(x/cellW)). DUST SEA — click sets st.next = clock so the worm breaches now, aimed at click-x (wm.xA derivation already parameterized on bx). ABYSSAL — click drops a pooled sonar ring; jellies within radius pulse (j.c spike) and drift one body-length toward it. VELOCITY — pointerdown boosts both riders' r.speed 2x for 800ms with trail alpha up (the trail buffer already encodes brightness via tb). Each also dispatches an Orrery event for the score.

- **Four of the five toys are silent — the score ignores their events** · `major`
  The toys dispatch CustomEvents 'consult' (06-worlds.js:1033), 'drill' (:1327), 'storm' (:1560), 'beacon' (:1776), but 07-audio.js only listens for 'preview', 'warp', 'scene', 'query', 'konami', 'sonar', 'artifact' (lines 477-519). Only aurora's 'Send a pulse' gets a chime ('query'). With the score on — which is the default-on design — pressing 'Light the beacons' produces a fully silent button press followed by fire two seconds later. Half the juice channel is dead for 80% of the toys.
  *Fix:* Add four listeners in 07-audio.js using the existing note()/taiko()/ping() vocabulary (~40 lines total): 'consult' → a quick descending 4-note roll in ARR.archive's scale (the dice-shimmer sound); 'drill' → two quartal blips + a taiko at the formation snap; 'storm' → a low filtered-noise swell reusing the whoosh() shape at half gain; 'beacon' → a rising fifth in ARR.beacons' scale, then schedule 6 delayed soft pings at BCN_STAGGER intervals so the audio chain lights with the pyres. Gate all with ready() and a 1s per-event rate limit like lastAnswer.

- **Button feel: no :active state anywhere, and toys swallow presses** · `major`
  A grep for ':active' across src/ returns zero styling hits. .w-toy (03-worlds.css:43-49) has only hover/focus states with 0.25-0.45s transitions — nothing acknowledges the press frame itself. Worse, presses can silently do nothing: the beacons run-guard (frame(): if (!st.sig.on && clock - st.lastEnd > 800) bcnRun(...)) means every click during the ~10s signal run is discarded with zero feedback, and call-drill's formation change is indistinguishable from the automatic 8.5s cycle (dySetForm is the same call the timer makes), so the press feels like coincidence.
  *Fix:* (1) Add a global pressed state: .w-toy:active, .return-orbit:active, #tour-toggle:active, .cta-btn:active { transform: translateY(1px) scale(0.97); transition-duration: 0.05s; } — one rule, respects rm since it's user-initiated. (2) During a beacons run, set aria-disabled + a dimmed .is-running class on #light-beacons (the FX already knows st.sig.on; flip the class from the click handler and clear it via setTimeout(runEnd - clock)). (3) Make manual drills FEEL manual: in the callDrill handler, set q.flash = clock + 400 on all 21 cadets so the squads visibly snap-acknowledge the order the timer never produces.

- **The Artifact's plate-reveal is undiscoverable and desktop-only** · `major`
  touchArtifact (05-core.js:391-406) fires the site's best secret — SphereForge.reveal(2600) on every third touch — but touches 1 and 2 produce identical ripples with no escalation tell, so nothing teaches the visitor to keep going. And 03b-deco.css:329-331 sets #artifact-hit, .artifact-label { display: none !important } under 700px, so on every phone the entire interaction (ripple, reveal, the 'artifact' audio answer, the aria surface) does not exist. The centerpiece object is untouchable for half the audience.
  *Fix:* Escalate the tell: pass artTouches % 3 into SphereForge.ripple() so ripple 2 is visibly larger + adds a brief plate-shudder (the skin-morph machinery already animates plates), and detune the artifactAnswer() a bit flatter each touch — a classic 'keep hitting it' ramp. On phone, the sphere IS visible (drawn dim at H*0.72); give it a hit surface there: re-enable #artifact-hit under 700px but position it with the same --ax/--ay/--ar the engine already writes (placeArtifactDom runs on phones too) and cap it at ART.r so it sits below the world column rather than over it — the current blanket display:none was solving an overlap that the smaller phone radius (min(W*0.34,150)) no longer causes if z-index drops under .orbits.

- **The warp has no anticipation frame, and mobile warp is a generic center flood** · `major`
  travel() (05-core.js:599-628) goes from click to full flood in the same frame — no wind-up. The clicked planet never acknowledges being chosen: the 1.18x hover swell doesn't spike, the ring doesn't flare, there is zero 'pull' before departure. And on phones, const p = desktop() ? planetPos(i, Ticker.clock) : { x: W/2, y: H/2 } means every mobile warp blooms from dead center — the flood loses its aim, and since phones have no hover state either, tap-to-travel is the entire mobile hub experience and it reads as a page transition, not a journey.
  *Fix:* Add a ~160ms departure beat: in travel(), set a departing = { slug, t0 } flag read by drawSky's drawWorld so the chosen planet eases to ~1.5x scale and full alpha while its ring brightens (one lerp on the existing hov path), and delay html.classList.add('warping') by those 160ms (travelTimer is already 495ms; keep total constant by landing at 495+160). On mobile, aim the flood at the tapped anchor: the .planet-anchor list rows have real getBoundingClientRect() centers — use the anchor's rect midpoint for --wx/--wy instead of W/2,H/2 so the streak burst originates from the world you touched.

- **The Grand Tour fights the player: any input kills it, and 'next stop' exists but is unreachable** · `major`
  TourController's CANCEL list ('pointerdown','keydown','wheel','touchstart', capture-phase, 05-core.js:693) ends the tour on ANY input — including clicking the audio toggle. A visitor who starts the tour and then turns the score ON to enjoy it kills the tour with that very click. Meanwhile advance() (line 767) is exported and never called by anything: a rider bored of a 9s DWELL on one world has no 'skip ahead' verb, only total cancellation.
  *Fix:* Whitelist the tour's own cockpit: in onInput, walk e.composedPath()/target.closest and ignore events originating on #audio-toggle and #tour-toggle (the tour button already has its own toggle-off handler; the suppressUntil dance becomes unnecessary for it). Then surface the dead verb: while running, ArrowRight (and a second small '>>' brass button next to the tour eye) calls advance() instead of cancelling — add 'ArrowRight-while-running' as an exemption in onInput before the stop(). Announce via the existing plateSay('Stop n of N'), which advance() already triggers through enterLeg.

- **The survey-log collection wipes every tab and pays out almost nothing** · `major`
  The progression loop stores 'orrery-surveyed' via store = sessionStorage (05-core.js:30-33, 461-469), so the collection resets on every new tab and return visit — 07-audio.js deliberately chose localStorage for the score opt-out with a comment calling session-scoped persistence a 'Smaug kill', yet the meta-game got the evaporating store. And the completion rite (maybeCompletionRite, 05-core.js:517-529) for surveying all ELEVEN worlds is: a 12px gold dot, borrowed aurora chime, and a 10-second hint-text swap. The konami code, which takes 10 keystrokes, earns a 16-second Colossus flyby; finishing the whole game earns less than the cheat code.
  *Fix:* Switch 'orrery-surveyed' (and 'orrery-survey-complete') to a localStorage-backed store — the same safeStore pattern 07-audio.js already ships — so the dots accumulate across visits and pull the visitor back. Then pay the completion properly: master surveyor triggers the Colossus flyby (08-konami.js's startFlyby is engine-adjacent; export it on Orrery.events via a 'mastery' event the konami fragment listens for), plus a one-shot golden konami-ring pulse on all eleven anchors (html[data-konami] machinery already does exactly this). Reduced-motion path keeps the static gold ring + seal.

- **Uncharted, the only pointer-reactive world, is dead to touch** · `minor`
  fx.draft (06-worlds.js:802-842) is the one world FX that responds to the visitor — the survey drafts under the pointer — but init sets st.auto = !matchMedia('(pointer: fine)').matches, so coarse-pointer devices get a canned autopilot orbit and taps do nothing (only pointermove is bound). On a phone, the world whose whole caption is 'Move the pointer: the survey drafts wherever you look' ignores the finger.
  *Fix:* Bind pointerdown alongside pointermove in fx.draft.init: on tap, set st.px/st.py to the tap point, suspend auto for ~4s (st.autoResume = clock + 4000, checked in frame before running the auto orbit), and triple the lighting rate for the tapped cell so a single tap visibly blooms a tile. Three lines of state, one extra listener, and the caption becomes true on touch.

- **The toys are all remote controls — no aimed, held, or continuous verb anywhere** · `minor`
  Every interaction on the site is a discrete fire-and-forget click: travel, ripple, and five 'press button, watch canvas react from across the room' toys (run-query, consult-archive, call-drill, brace-wall, light-beacons). There is no aim, no hold, no drag, no direct manipulation of any simulated object — the verbs live in the card UI, not in the worlds. The drillyard simulation literally contains a targeting system (the lance picks shooter and victim via reservoir sampling, 06-worlds.js:1244-1254) that the player is never handed.
  *Fix:* Promote one toy per release to direct manipulation. Cheapest: DRILLYARD — click on the canvas fires the lance from a random cadet at the cadet nearest the click (project-space nearest over q.sx/q.sy is a 21-element scan; the freeze/rescue drama that follows is already fully built and is the payoff). Second: STORMWALL — press-and-HOLD 'Brace for the wall' pins the buds closed (b.o target 0.06 while held via a pointerdown/pointerup pair on the existing button) so releasing during a storm teaches the trust mechanic kinesthetically. Both reuse existing simulation state; neither adds a particle.

- **The keyboard is a first-class citizen with only two verbs** · `polish`
  Keyboard travelers get Tab-cycle + Enter (hub) and Esc (world) — that's the whole map, despite the hub hint advertising keyboard play and the konami listener proving global keydown handling is already safe (08-konami.js filters inputs/modifiers correctly). Inside a world there is no prev/next, so sampling all 11 worlds by keyboard is world → Esc → Tab×n → Enter, eleven times. And in the Grid — the world about typed glyphs — keystrokes do nothing.
  *Fix:* One keydown handler in 05-core.js beside the Esc handler: inside a world, ArrowLeft/ArrowRight travels to WORLDS[i±1 mod 11] via the existing travel() (respects warp, survey marking, score events); digits 1-9,0 warp from the hub to that world index. In the Grid only, any printable keydown ignites the white trace in a random column (reuse the nextTrace branch) — the rain visibly answers your typing while keeping the 'decorative glyphs only' law, since the drawn glyph stays random. ~25 lines, all through existing public paths.

## MITHRIL — Seat of Art Direction & Visual Craft (tokens, type, light, and the eleven faces)

**Verdict.** The engineering-of-art here is genuinely high craft — seeded determinism in PlanetForge, designed reduced-motion poses, prebaked sprite lighting — but the art direction has three systemic gaps that keep it at "excellent codepen" rather than "film frame." First, the entire Deep Deco fiction (engraved brass, cream lettering, Commission plates) is set in Segoe UI/Roboto at weight 300, which is a per-OS lottery and reads as an admin dashboard wearing a costume. Second, the Artifact's hand-made skin renders are the single most beautiful assets in the repo, and bandFor() shreds them into anonymous scrolling gold streaks — the orrery dial face, the whole reason the hub skin exists, never survives to the screen. Third, several atmosphere layers are painted so timidly they are sub-perceptual (grain at 0.05 overlay on near-black, the porthole ring at 0.11 alpha, the orbit ring at 0.10), so the "instrument through a porthole" story exists in the CSS comments more than on the monitor. The seven original worlds pass the one-second trope test; the four v6 additions (storm/drill/archive/beacons) collapse into one indigo family with two nearly identical light-blue accents. And the phone — a hard constraint — gets the brochure list with a half-alpha blob behind it, not the orrery. Everything below is fixable inside the house rules; most of it is color values, one font file, and about a hundred lines of canvas.

### Findings

- **The type stack squanders the entire fiction** · `CRITICAL`

## MITHRIL — Bellfounder, seat of Score & Sound Design

**Verdict.** The dread engine in 07-audio.js is the most disciplined synth graph I've seen shipped without a library: an 8-node persistent chain, scene-scoped rigs, per-note transients that clean up after themselves, and a toggle whose label genuinely never lies. Eleven original arrangements with real character choices (hub's minor-second dread over a 25s mostly-rest cycle, archive's lydian, beacons' horn calls) — the composition brief was taken seriously. But as a SCORE it is a jukebox of 16-step screensavers: `stepIdx % span` replays the identical motif verbatim forever, so every world flatlines into wallpaper inside 90 seconds of a 3-minute visit. Worse, the score is deaf and blind: four of the five toy buttons dispatch events that no listener anywhere consumes, the return trip home is sonically unmarked, nothing visual moves on the beat, and the entire percussion section lives below 90Hz where a mid-range phone speaker reproduces nothing — the hub heartbeat, the signature dread device, does not exist on the device the house rules say must stay delightful. The instrument is built; v7's job is to make it listen, develop, and conduct.

## MITHRIL — Seat of Performance, Mobile & Accessibility (the one who profiles on a $180 phone)

**Verdict.** The engineering discipline here is real and mostly honored: one ticker with self-removing tasks, one live FX canvas per scene, pooled particles, prebaked sprites, DPR capped, an audio label that never lies, and a keyboard path (focus tint, Esc, focus-restore, h2 landing) better than most production apps. But the frame has a desktop-shaped hole: the entire jaw-drop — orbiting planets, occlusion, the Artifact wearing faces — is gated on hover and >700px, so every phone gets a brochure list with a ghost behind it, while simultaneously being force-fed 3.4MB of skin webps it can never display; that is the single worst byte-to-delight ratio in the piece. The boot bakes ~12M+ noise evals synchronously at the exact brochure→app flip, the hub loop runs at native refresh forever (120Hz phones pay double for a 10Hz twinkle), and a URL-bar collapse restarts an entire world mid-scroll. Reduced-motion coverage is 9/11 worlds, not 11/11 — Uncharted goes blank, and no-JS Arcadia is an empty box — which matters because the house rule is absolute. Accessibility is strong until you hit forced-colors, where the Artifact's focus ring simply vanishes. None of this needs new architecture; it needs the mobile/touch path promoted from fallback to first-class, and about six surgical patches to the engine's edges.

### Findings

- **3.4MB of Artifact skins are prefetched unconditionally — 10x the page, unreachable on the devices that pay most for it** · `CRITICAL`
  SphereForge.init() (src/05c-sphereforge.js:335-338) staggers loadSkin() for all 9 webp skins (assets/artifact/, 3.4MB total; the page itself gzips to ~90KB) starting 1.4s after boot on EVERY load — phone, reduced-motion, deep-linked-into-a-world, save-data, doesn't matter. On <=700px the Artifact hit/label are display:none !important (03b-deco.css:329-331) and the face-swap is hover-driven (pointerenter/focus in 05-core.js:445-448), so a phone downloads ~3MB of images it can never display. Worse, memory is never released: each hovered skin bakes a 2048x512 RGBA band canvas (~4.2MB each, bandFor() 05c:280-290) AND keeps the decoded Image in `skins` forever — a full tour of faces retains ~40-70MB on a low-RAM phone.
  *Fix:* Delete the unconditional stagger. Gate prefetch on matchMedia('(hover:hover) and (pointer:fine)').matches && innerWidth>700 && !navigator.connection?.saveData, and warm it on intent instead (first pointerenter on any .planet-anchor prefetches the remaining skins). setSkin() already lazy-loads on demand and draw() already waits for rec.ready, so nothing breaks — first hover just crossfades ~300ms later. Free memory: after bandFor() bakes a band, null out rec.img (the Image is never read again), and keep an LRU of ~3 band canvases, rebaking on re-entry (bake is one drawImage, cheap).

- **The marquee mechanic is hover-only: every touch user — including every phone — gets a brochure list and a ghost** · `CRITICAL`
  This is a frame problem, not a detail. The v5-v7 headline features — orbiting PlanetForge planets, occlusion behind the gold, the Artifact answering your attention with a face — exist only in the >700px orbit layout driven by pointerenter/focus (05-core.js:429-449). On a phone: .orbits is a static row list (02-hub.css:154-158), the sphere is painted at globalAlpha 0.5 at H*0.72 BEHIND the glass list rows (05-core.js:299-305), and #artifact-hit is hidden so touchArtifact/ripple/reveal are unreachable. On an iPad in the desktop layout, tap fires pointerenter+click together, so travel() starts before the 650ms face crossfade (FADE_MS, 05c:265) is ever visible. The house rule says 'must stay delightful on a mid-range phone'; today the phone gets roughly the no-JS brochure plus a glow.
  *Fix:* Give touch a first-class hub. (1) Phone: put a compact live orbit above the list — Artifact centered at ~H*0.30 in the space under the plaque, 5-6 planets on a tightened ellipse, anchors' 44px targets riding them (the engine already writes --pax/--pay; it's a measureOrbit() branch, not new machinery), keep the full list below as the index. (2) Restore #artifact-hit on phone at its drawn position — tap-to-ripple and the 3-touch reveal are exactly the toy touch users love, and it steals no scroll if it only covers the sphere. (3) On (hover:none), make first tap on an anchor = preview (setSkin + tint + label), second tap or a 'Travel' chip = travel(); one `previewedSlug` latch in the click handler.

- **Reduced-motion / no-JS coverage matrix has two holes: Uncharted (rm) and Arcadia (no-JS) are stripped scenes, not designed end-states** · `major`
  The house rule is 'designed end-states, never stripped scenes', and 9 of 11 worlds honor it — but fx.draft has no rm() (06-worlds.js:802-842) and 03-worlds.css has no html.rm rule for uncharted: under reduced motion WorldFX.start() runs `fx[name].rm && fx[name].rm()` (06:29) and paints nothing, so an rm visitor gets a bare blueprint grid with zero survey — and if the user flips rm ON inside the world, stopAll() clears the canvas to blank in front of them. Arcadia has the inverse hole: fx.arcadia.rm() paints a lovely held frame, but there is no html:not(.js) rule for its canvas (confirmed by grep; every other canvas world has one), so the no-JS brochure shows an empty black box under the CRT vignette.
  *Fix:* Uncharted: add fx.draft.rm() that seeds `lit` deterministically (e.g. a diagonal swath of cells at v=0.3-1.0 plus a few >0.65 survey arcs) and paints one frame — ~15 lines reusing the existing frame loop body. Arcadia: either add a small .arc-static SVG pose (invader row + player ship, same shapes as arcStatic) shown under html:not(.js), or accept CSS-only: a repeating-gradient invader-rank stand-in like the .mesa-skyline fallback idiom (03-worlds.css:93-100).

- **Boot bakes ~12M+ noise evaluations synchronously at the worst possible moment (the brochure→app flip)** · `major`
  bootOrrery() (05-core.js:808-820) runs PlanetForge.init(WORLDS) — eleven 512x256 per-pixel fBm textures, several with 3 noise fields each, plus clouds and the grid's double layer — then SphereForge.init() bakes a 768x288 texture sampling FOUR fbm fields per pixel (05c:101-125) plus a 512x128 flow layer. That is on the order of 10-20M smoothstep-bilinear evals on the main thread, immediately after html.classList.add('js') has re-layouted the whole stacked brochure into fixed scenes. On a mid-range phone this is a few hundred ms of block: first input during arrival eats it (INP/TBT), the approach cinematic's first frames can stutter, and the brochure-flash before the flip gets longer.
  *Fix:* Stage the bake. Frame 0 needs only: the sphere (its texture, ~2.7M evals) and nothing else — planets can pop in over the next few frames. Split PlanetForge.init into initShared() + buildWorld-on-demand: bake worlds in a rIC/setTimeout(0) chain in WORLDS order (draw() already no-ops for missing slugs — add a fade-in alpha when a planet's texture lands, which reads as the orrery 'waking'). Optionally halve TEX_W/TEX_H when matchMedia('(max-width:700px)') — on a phone no planet is ever drawn bigger than ~34px, and the sphere band is invisible detail at R<=150.

- **No frame governor: the ticker runs at native refresh and the hub loop never drains** · `major`
  Ticker (05-core.js:38-55) is dt-correct but paints every rAF: a 120Hz iPhone/Pixel does exactly double the canvas work (24 sphere band blits + up to 460 per-star arc()+fill() with a string concat per star + planets) for zero visible gain — twinkle and molten drift are sub-10Hz phenomena. And the 'stops when idle' claim is only technically true: skyTask returns true forever, so on the hub the loop runs for the entire session; there is no interaction-idle demotion and no battery/low-power hook. This is the single biggest sustained battery cost in the piece.
  *Fix:* Add a min-frame interval to Ticker: accumulate dt and skip the task pass when now-lastPaint < budget (16.6ms default). Expose Ticker.setBudget(ms) and set 33ms (30fps) when matchMedia('(max-width:700px)').matches — ambient starfield/sonar at 30fps is visually indistinguishable on a phone. Cheap extra: after ~60s with no pointermove/keydown/scroll on the hub, drop to 30fps everywhere and restore on first input (2 timestamps, no new architecture).

- **Mobile URL-bar collapse restarts the whole world scene via the resize handler** · `major`
  The debounced resize handler (05-core.js:87-94) unconditionally runs sizeSky() (rebuild stars, re-measure orbit) and, inside a world, WorldFX.start(Scenes.current) — which calls stopAll() then re-inits the FX from scratch. On mobile, scrolling a world card toggles the browser chrome and fires resize with a height-only delta: the dunes re-roll their ridges, the beacon chain forgets its signal, the storm resets to calm, mid-scroll, every time. It reads as a glitch and costs a full re-init on the slowest devices.
  *Fix:* Track lastW/lastH in the handler. If width is unchanged and |dH| < ~140px (URL-bar territory), only update the canvas backing size cheaply (or do nothing: .fx-canvas is inset:0 with CSS 100% sizing, so a small letterbox stretch is invisible) and skip both buildStars() and WorldFX.start(). Full rebuild only on width change or orientationchange — which is exactly the 'rotated phone' case the comment (Smaug kill 8) was written for.

- **Forced-colors / high-contrast mode erases the Artifact's focus indicator (and friends)** · `major`
  #artifact-hit:focus-visible sets `outline: none` and paints the ring with box-shadow (03b-deco.css:309-312). Windows High Contrast / forced-colors strips box-shadow entirely, so the only focus indication on the page's centerpiece control vanishes — a keyboard HCM user tabs onto an invisible 500px disc with no feedback. The chamfered controls (.brand, .return-orbit, .audio-toggle, .w-toy) survive because they keep a real outline (offset -4px), but every inset box-shadow 'double rule' and the .survey-dot fills also disappear, leaving the survey log unreadable (dots convey state by background only).
  *Fix:* For #artifact-hit, use `outline: 2px solid transparent; outline-offset: -4px` alongside the box-shadow — forced-colors repaints transparent outlines in Highlight color, normal mode shows the gold shadow. Add one `@media (forced-colors: active)` block: give .survey-dot.is-surveyed a `border: 4px solid` / background CanvasText so state survives, and give .planet-anchor a visible border in app mode (it currently relies on canvas + glow alone).

- **Per-frame DOM style churn on the hub: 5 writes x 11 anchors with CSS transitions being retargeted every frame** · `minor`
  drawWorld() (05-core.js:259-291) writes --pax/--pay/--psize/--pdim and zIndex on every anchor every frame. --pdim feeds `.pa-label { opacity: var(--pdim); transition: opacity 0.3s }` (02-hub.css:131) and --psize feeds .pa-dot's transitioned transform sizing — so 11 labels have a 0.3s opacity transition retargeted 60-120 times per second, forever. Each custom-prop write invalidates the anchor's subtree style. It works, but it's a constant style-recalc tax stacked on top of the canvas work, and zIndex flips force sibling repaint checks.
  *Fix:* Write only on meaningful delta: cache last written values per anchor and skip when |d| < 0.5px / 0.02 dim / same z-band (depth crosses 0 rarely). Remove the CSS opacity transition from .pa-label in app mode — the engine already produces continuous values, CSS easing on top adds nothing but transition machinery (keep it for :hover snap via a class instead). While in there: hoist the per-star `s.hue + alpha + ')'` string concat (05-core.js:234) by quantizing twinkle to ~8 alpha buckets pre-concatenated per hue — kills ~460 string allocs/frame.

- **Phone compositing stack: backdrop-filter cards over a live canvas plus two blend/fixed overlays** · `minor`
  .world-card keeps .glass's backdrop-filter: blur(14px) saturate(1.3) (01-tokens.css:159-164) while sitting on top of a full-screen canvas that repaints every frame — the browser re-blurs the card region continuously, which is among the most expensive per-frame effects on a mid-range GPU. Above that: .grain is a full-viewport fixed layer with mix-blend-mode: overlay (03b-deco.css:119-125) forcing the page under it through an offscreen blend on every repaint, plus .porthole and the hub's animated .scene-hub::before at inset:-30% with will-change (a ~1.7x-viewport composited layer). Individually fine on desktop; together they are a real slice of the phone frame budget.
  *Fix:* Under @media (max-width:700px): drop backdrop-filter from .world-card.glass (its background-color is already rgba(6,22,18,0.8) — bump to 0.9 and nobody can tell), swap .grain to mix-blend-mode: normal with opacity ~0.035 (visually near-identical on the dark void), and consider skipping the dust-drift layer (it's behind the list rows anyway). Keep all of it on (min-width:701px).

- **The Konami brand-tap counter hijacks real clicks on the DDL home link** · `minor`
  The touch rite (08-konami.js:177-189) calls e.preventDefault() on every pointer click of .brand, then navigates via `location.href` after a 480ms timeout if the tap was 'lone'. Consequences: every genuine click on the masthead link is delayed half a second; cmd/ctrl-click and middle-click intent (open in new tab) is destroyed — the modifier click is preventDefault'ed and later re-navigates the CURRENT tab; and SPA-back behavior differs from a real anchor activation.
  *Fix:* Bail out before preventDefault when e.metaKey || e.ctrlKey || e.shiftKey || e.button === 1 (let the browser do its thing; a modified click also shouldn't count toward the seven). For plain clicks, shrink the lone-tap delay to ~250ms, or better: only start intercepting after the SECOND tap inside the 4s window — first tap navigates natively with zero delay, and the rite still works because tap 2..7 arrive on the un-navigated page only when someone is deliberately hammering.

- **SR/keyboard polish: the only usage instructions are aria-hidden, and four worlds have no Artifact face** · `polish`
  The keyboard path is genuinely excellent (focus tint, Esc, focus restore on return at 05-core.js:560-564, h2 focus on arrival, honest audio label states). Two rough edges: (1) .hub-hint — 'Tab to cycle · Enter to travel' — is aria-hidden="true" (04-body.html:37), so screen-reader users get zero orientation for the app mode they actually land in; (2) SKIN_OF (05c-sphereforge.js:260-263) maps only 7 of 11 worlds, so hovering/focusing Archive, Drillyard, Stormwall, or Beacons silently falls back to the hub face — for a keyboard user tabbing the ring, 4 of 11 stops produce no response from the thing the README promises 'answers you'.
  *Fix:* (1) Add a visually-hidden paragraph inside the nav ('11 links follow; Enter travels to a world, Escape returns to orbit') — one .sr-only class, and leave .hub-hint decorative. (2) Either commission the 4 missing skins, or map them to the nearest existing faces (archive→uncharted, drillyard→machine, stormwall→veins, beacons→molten) so the answer never goes mute; the SKIN_OF table is the one-line change.
